<section>
  <h2>Why a queue instead of one ZIP</h2>
  <div class="grid">
    <div class="step"><h3>Because batches fail at the end, not the start</h3>
      <p>A browser archive has to be held in memory until every song is inside it. On a 30-song run that means one slow track or one
         dropped connection can take the whole batch with it — you wait, you fail, you start over.</p></div>
    <div class="step"><h3>So each song lands on its own</h3>
      <p>Every finished track is written to your disk the moment it completes. Interrupt the run and you keep what already arrived;
         resume and the rest carries on. Nothing is re-downloaded to rebuild an archive.</p></div>
    <div class="step"><h3>And you see the real state of every song</h3>
      <p>The list marks each track as it goes — kept, waiting, or skipped because something about it was not readable. No silent
         "done" over a half-full folder.</p></div>
  </div>

    qlist.innerHTML = songs.map(function(s, i){

      return '<li>' +

    }).join('');

  }

  qlist.addEventListener('change', function(e){
    var i = e.target.getAttribute('data-i');
    if (i !== null) songs[+i].picked = e.target.checked;
  });

  selAll.addEventListener('click', function(){
    var any = songs.some(function(s){ return !s.picked; });
    songs.forEach(function(s){ s.picked = any; });
    render();
  });

  scan.addEventListener('click', function(){
    var v = (url.value || '').trim();
    if (!v) { url.focus(); return; }
    scan.disabled = true;
    note.hidden = true;
    queue.hidden = false;
    qstatus.textContent = 'Reading the list…';
    fetch('/api/list?url=' + encodeURIComponent(v))
      .then(function(r){ return r.json(); })
      .then(function(d){
        if (d.error) throw new Error(d.error);
        songs = (d.songs || []).map(function(s){
          return { id: s.id, title: s.title, picked: true, state: 'idle',
                   label: s.video ? 'video' : 'audio only' };
        });
        if (!songs.length) throw new Error('That link has no public songs in it.');
        render();
        qstatus.textContent = '';
      })
      .catch(function(err){
        queue.hidden = true;
        note.hidden = false;
        note.textContent = err.message || 'That link could not be read. Check that it is public and try again.';
      })
      .then(function(){ scan.disabled = false; });
  });

  run.addEventListener('click', function(){
    var picked = songs.filter(function(s){ return s.picked; });
    if (!picked.length || running) return;
    running = true; run.disabled = true; selAll.disabled = true;
    qprog.style.width = '0%';
    var done = 0, kept = 0;

    (function next(i){
      if (i >= picked.length) {
        running = false; run.disabled = false; selAll.disabled = false;
        qstatus.textContent = kept + ' of ' + picked.length + ' kept';
        return;
      }

      s.state = 'idle'; s.label = 'keeping…'; render();
      fetch('/api/keep?id=' + encodeURIComponent(s.id))
        .then(function(r){ return r.json(); })
        .then(function(d){
          if (d.error) throw new Error(d.error);
          // One finished file per song — the browser is never handed an archive.
          if (d.url) {
            var a = document.createElement('a');
            a.href = d.url; a.download = d.filename || '';

        .catch(function(err){
          s.state = 'failed'; s.label = err.message || 'could not be kept';
        })
        .then(function(){
          done++;
          qprog.style.width = Math.round(done / picked.length * 100) + '%';
          render();
          next(i + 1);
        });
    })(0);
  });

五、上线前三个提醒
接口要真的实现，别让按钮空转。 页面上 Read the list 打 /api/list?url=…、Keep selected 打 /api/keep?id=…，两个端点都得有真返回（列表要带 video: true/false 字段，才能把「audio only」标对）。批量逐首拉、逐首写盘这条在服务端和前端都要成立——前端的 a.download 一次只交一个文件，正是为了不把整批塞进内存。
导航链接可能有一处不统一，趁这页一起定死。 批次表里 Suno WAV 那页是 /suno-wav-downloader/，而前几页（Udio 页、这页）的导航里我写的是 /suno-to-wav/。两个只能留一个，上线前统一一次，别让同一批页面的导航各自指向不同的 URL。
扩展那一段不要删。 「Suno bulk download Chrome extension」和「Suno tracks Exporter extension」这两条相关搜索就排在第一页第 2 名（Chrome 应用商店）那一带——它证明有一批人的真实动作是去装扩展。用一张对比表正面回答「要不要装扩展」，比装作没这回事更能留住人，而且它顺便解释了为什么我们不碰 suno.com 页面本身。
